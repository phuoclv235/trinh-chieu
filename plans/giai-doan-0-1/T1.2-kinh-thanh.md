# T1.2 `Scripture`: địa chỉ câu, kho bản dịch, chia trang

**Model:** Opus 5.5 · **Phụ thuộc:** T1.1 · **Ước lượng:** 4 ngày · **Chạy:** Linux

## 1. Danh mục sách (`BookCatalog`)

## 2. Phân tích địa chỉ câu (`ReferenceParser`)

```swift
public struct ScriptureReference: Sendable, Hashable, Codable {
    public var ranges: [VerseRange]          // theo thứ tự người dùng gõ
    public var canonical: String             // "Giăng 3:16-18"
}
public struct VerseRange: Sendable, Hashable, Codable {
    public var book: String                  // OSIS
    public var startChapter: Int, startVerse: Int?    // nil = cả chương
    public var endChapter: Int, endVerse: Int?
}
public struct ReferenceParser: Sendable {
    public init(catalog: BookCatalog)
    public func parse(_ input: String) -> ParseResult
    public func bookCandidates(_ prefix: String, limit: Int = 5) -> [Book]     // cho gợi ý khi đang gõ
}
public enum ParseResult: Sendable, Equatable {
    case reference(ScriptureReference)
    case ambiguousBook(candidates: [Book], rest: String)
    case incomplete(book: Book)              // mới gõ tên sách
    case invalid(reason: String)             // thông điệp tiếng Việt
}
```

So khớp tên sách trên chuỗi đã `VietText.foldLoose` và bỏ hết khoảng trắng:

1. Số đứng đầu: "1", "2", "3", "i", "ii", "iii" (có hoặc không có khoảng trắng) là số thứ tự sách.
2. Khớp chính xác với một `alias` hoặc `shortVi` hoặc `nameVi` đã gộp: chọn sách đó.
3. Không thì khớp tiền tố: nhiều ứng viên thì xếp theo **bảng ưu tiên dùng nhiều** cố định trong `books-vi.json` (trường `priority`, nhỏ là ưu tiên). Bảng ưu tiên mặc định: Giăng 1, Thi-thiên 2, Rô-ma 3, Ma-thi-ơ 4, Ê-sai 5, Lu-ca 6, Sáng-thế Ký 7, Công-vụ 8, Châm-ngôn 9, Hê-bơ-rơ 10, Ê-phê-sô 11, Phi-líp 12, Mác 13, Gia-cơ 14, Khải-huyền 15, các sách còn lại theo thứ tự quy điển cộng 100. Ứng viên đầu có ưu tiên tốt hơn hẳn (chênh nhau từ 5 trở lên) thì chọn luôn; không thì trả `ambiguousBook`.
4. Alias bắt buộc phải có: "gi" → Giăng, "giang" → Giăng, "thi" → Thi-thiên, "tt" → Thi-thiên, "ro" → Rô-ma, "mat" → Ma-thi-ơ, "sa" → Sáng-thế Ký, "xuat" → Xuất, "cv" → Công-vụ, "kh" → Khải-huyền, "1co" → I Cô-rinh-tô, "he" → Hê-bơ-rơ. Tên tiếng Anh cũng nhận ("john 3 16").

Phần chương câu chấp nhận: `3:16`, `3 16`, `3.16`, `3,16`, `3:16-18`, `3:16 - 18`, `3:16-4:2`, `3` (cả chương), `3-4` (nhiều chương), danh sách bằng `;` (`Giăng 3:16; 4:1-3`) và `,` sau dấu hai chấm (`3:16,18` nghĩa là câu 16 và 18). Thiếu sách ở phần sau `;` thì dùng sách trước.

Kiểm phạm vi dựa trên bản dịch (số chương, số câu) nằm ở `BibleStore`, không ở bộ phân tích.

Bộ test phải có ít nhất 60 ca, gồm: "gi 3 16", "Giăng 3:16-18", "giang3:16", "1 co 13", "I Cô-rinh-tô 13:4-7", "1co13:4", "thi 23", "Thi-thiên 119:105", "ro 8:28; 12:1-2", "mat 5:3,5,7", "khai 21:1-4", "sa 1:1", "john 3:16", "a" (ambiguous), "1" (invalid), "gi 3:16-2" (invalid: câu cuối nhỏ hơn câu đầu).

## 3. Kho bản dịch (`BibleStore`)

```swift
public actor BibleStore {
    public init(directory: URL)                               // thư mục bibles/
    public func translations() throws -> [TranslationInfo]    // code, name, language, license
    public func open(_ code: String) throws -> BibleTranslation
}
public final class BibleTranslation: Sendable {               // chỉ đọc, an toàn đa luồng; mỗi luồng một kết nối hoặc một hàng đợi nối tiếp
    public let info: TranslationInfo
    public func books() -> [BookInfo]                          // sách có trong bản dịch, số chương
    public func verseCount(book: String, chapter: Int) -> Int
    public func verses(_ ref: ScriptureReference) throws -> [Verse]   // ném lỗi tiếng Việt khi ngoài phạm vi: "Giăng chỉ có 21 chương"
    public func allVerses() -> AnySequence<Verse>             // cho lập chỉ mục
}
public struct Verse: Sendable, Equatable { public var book: String, chapter: Int, verse: Int, text: String }
```

Lược đồ tệp như `docs/dinh-dang-tep.md` mục 5. `verses` nhanh: dưới 1 ms cho một đoạn 10 câu (đo trên CI).

Hàm `BibleStore.write(code:info:books:verses:)` để bộ nhập (T1.4) tạo tệp, ghi vào tệp tạm rồi đổi tên.

## 4. Chia câu thành trang (`ScriptureSlideBuilder`)

```swift
public struct ScriptureSlideBuilder: Sendable {
    public func slides(for ref: ScriptureReference, verses: [Verse], translationName: String,
                       options: ScriptureLayoutOptions) -> [Slide]
}
public struct ScriptureLayoutOptions: Sendable { public var maxCharactersPerSlide: Int; public var showReference: Bool; public var verseNumbers: VerseNumberStyle }
```

Quy tắc:

1. Gom câu liên tiếp vào một trang khi tổng ký tự (kể cả số câu) không vượt `maxCharactersPerSlide`.
2. Một câu dài hơn giới hạn thì tách tại ranh giới câu văn (". ", "; ", ": ", ", ") gần giữa nhất mà mỗi phần không vượt giới hạn; không có thì tách tại khoảng trắng gần giữa. Không bao giờ cắt giữa một từ.
3. Mỗi trang có phần tử chữ `slot = body` chứa nội dung (số câu dạng chỉ số trên, ký hiệu bằng ký tự Unicode chỉ số trên "¹⁶" khi `verseNumbers = superscript`), và nếu `showReference` thì một phần tử chữ `slot = reference` ghi địa chỉ của riêng các câu trên trang đó cùng tên viết tắt của bản dịch, ví dụ "Giăng 3:16–17 (TT1925)".
4. `id` của trang sinh tất định từ (mã bản dịch, sách, chương, câu đầu, phần tách), để `contentDidChange` và nhật ký nhận ra cùng một trang.

## Tiêu chí nghiệm thu

1. Đủ 60 ca phân tích ở mục 2, đều xanh.
2. Tạo một bản dịch giả 3 sách trong test, tra được, báo lỗi ngoài phạm vi bằng tiếng Việt.
3. Chia trang: câu dài 600 ký tự với giới hạn 220 ra 3 trang, không cắt giữa từ; id tất định giữa hai lần chạy.
4. Test chạy lặp 3 lần xanh trên Linux.
