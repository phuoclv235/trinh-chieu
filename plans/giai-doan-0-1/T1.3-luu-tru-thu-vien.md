# T1.3 `LibraryStore`: đọc ghi, theo dõi, thùng rác, gói mang đi

**Model:** Opus 5.5 · **Phụ thuộc:** T1.1 (và T1.2 cho phần lập chỉ mục câu) · **Ước lượng:** 4 ngày · **Chạy:** Linux (theo dõi thư mục chỉ test trên Mac)

## Mục tiêu

Thư viện là nguồn sự thật duy nhất trên đĩa theo `docs/dinh-dang-tep.md`. `LibraryStore` giữ toàn bộ tài liệu trong bộ nhớ (thư viện điển hình dưới 50 MB JSON), ghi an toàn, giữ chỉ mục đồng bộ và cung cấp dữ liệu đồng bộ cho `ShowController`.

## API

```swift
@MainActor @Observable public final class LibraryStore {
    public static func open(at root: URL, fileWatcher: any FileWatching) async throws -> LibraryStore   // tạo cấu trúc nếu trống
    public private(set) var info: LibraryInfo
    public private(set) var presentations: [UUID: Presentation]
    public private(set) var themes: [UUID: Theme]
    public private(set) var plans: [UUID: ServicePlan]
    public private(set) var media: [MediaID: MediaAssetInfo]
    public private(set) var loadProblems: [LoadProblem]        // tệp hỏng, tệp từ phiên bản mới hơn; hiện trên giao diện

    public func save(_ p: Presentation) ; public func save(_ t: Theme) ; public func save(_ s: ServicePlan)   // cập nhật bộ nhớ ngay, ghi đĩa có hoãn 1 giây theo id
    public func flush() async                                  // ghi mọi thứ đang hoãn; gọi khi thoát ứng dụng
    public func moveToTrash(_ ids: [UUID]) throws -> TrashTicket
    public func restore(_ ticket: TrashTicket) throws          // Hoàn tác xoá
    public func importMedia(from url: URL) async throws -> MediaAssetInfo   // băm SHA-256 theo luồng, chép vào media/, trùng thì trả bản có sẵn
    public func mediaURL(_ id: MediaID) -> URL?
    public func search(_ q: String, kinds: Set<IndexKind>) async -> [SearchHit]
    public func exportBundle(planID: UUID, to: URL) async throws
    public func exportBundle(presentationIDs: [UUID], to: URL) async throws
    public func inspectBundle(at: URL) async throws -> BundleInspection        // liệt kê nội dung và xung đột id
    public func importBundle(at: URL, resolutions: [UUID: ConflictResolution]) async throws
    public var changes: AsyncStream<LibraryChange> { get }    // cho ShowController.contentDidChange và giao diện
}
```

`LibraryStore` cũng hiện thực `ShowContentProvider` (qua một kiểu bọc trong T1.5, vì cần `BibleStore` và mẫu mặc định).

## Quy tắc

1. **Mở thư viện:** đọc `library.json` (thiếu thì tạo mới với 3 mẫu mặc định từ T1.5; trong T1.3 dùng mẫu tối thiểu, T1.5 thay). Đọc song song mọi tệp JSON bằng `TaskGroup`, chạy `Migration` trên từng tệp; tệp được migrate thì ghi bản `.bak` cạnh tệp gốc trước khi ghi đè. Tệp lỗi đưa vào `loadProblems`, không chặn việc mở.
2. **Ghi:** nguyên tử (tệp `.tmp` rồi `rename`), đặt `modifiedAt = now`. Hoãn 1 giây theo id; lệnh `save` mới huỷ lần ghi hoãn trước của cùng id.
3. **Chỉ mục:** mỗi lần ghi hoặc xoá thì cập nhật `LibraryIndex` (thân bài hát là toàn bộ chữ các trang; tiêu đề phụ là số thánh ca và tác giả). Khi mở, so `modifiedAt` của từng tệp với chỉ mục và cập nhật phần chênh; chỉ mục trống thì dựng toàn bộ ở nền và cho phép tìm dần.
4. **Theo dõi thay đổi ngoài ứng dụng** (thư viện đặt trong iCloud Drive, Dropbox): giao thức `FileWatching`; bản Mac dùng FSEvents (đặt trong `TrinhChieuMedia` hoặc App vì cần CoreServices), bản Linux và test dùng bản giả. Tệp đổi trên đĩa mà không do Hệ thống ghi (so nội dung với bản trong bộ nhớ) thì nạp lại và phát `LibraryChange`. Nếu id đó đang có thay đổi chưa ghi thì **không** ghi đè: giữ bản trong bộ nhớ, ghi bản đĩa thành `<uuid>.conflict-<thời điểm>.json` và báo trong `loadProblems`.
5. **Xoá:** chuyển vào `.trash/<uuid>.<thời điểm>.json`; `TrashTicket` giữ đủ để `restore`. Khi mở thư viện, xoá hẳn tệp trong `.trash/` cũ hơn 30 ngày. Xoá bộ trình chiếu đang nằm trong chương trình: vẫn xoá, mục trong chương trình hiện "Không tìm thấy" (không tự sửa chương trình).
6. **Media** (`MediaAssetInfo` có trường `origin` theo `docs/dinh-dang-tep.md`; giai đoạn 1 chỉ tạo `copied`, đọc được `linked` mà không lỗi, `mediaURL` của media liên kết trả bản trong `.cache/media/` nếu có, không thì `nil`): tên tệp `media/<12 ký tự hex đầu của SHA-256>.<đuôi gốc viết thường>`; `MediaAssetInfo` ghi ở `media/<id>.json`. Thông tin kích thước, thời lượng, ảnh thu nhỏ do `MediaImport` (T1.4, phía Mac) điền sau; T1.3 chỉ ghi tên gốc, kích thước tệp, kiểu theo đuôi.
7. **Gói mang đi:** như `docs/dinh-dang-tep.md` mục 7, dùng ZIPFoundation (thêm vào `Package.swift` cho target `LibraryStore`). Gói một chương trình gồm: chương trình, mọi bộ trình chiếu nó dùng, mọi mẫu được tham chiếu, mọi media được tham chiếu. Không gói bản dịch Kinh Thánh (ghi mã bản dịch trong `manifest.json`; thiếu khi mở thì báo).
8. **Nhật ký buổi nhóm:** hiện thực `ServiceLogSink`, ghi `logs/` theo lô mỗi 5 giây và khi `flush`.

## Tiêu chí nghiệm thu

1. Tạo thư viện mới trong thư mục tạm, lưu 100 bộ trình chiếu, đóng, mở lại: dữ liệu giống hệt; tìm kiếm ra đúng.
2. Ghi bị ngắt giữa chừng (giả lập bằng cách để lại tệp `.tmp`): khi mở, tệp gốc nguyên vẹn, `.tmp` bị dọn.
3. Tệp `schemaVersion: 99` vào `loadProblems` với thông điệp "Tệp được tạo bởi phiên bản Hệ thống mới hơn", các tệp khác vẫn mở.
4. Xoá rồi hoàn tác khôi phục đúng tệp; tệp trong thùng rác quá 30 ngày (đồng hồ giả) bị dọn.
5. Xuất gói một chương trình rồi nhập vào thư viện trống: đủ tài liệu và media; nhập lần hai báo xung đột đúng id.
6. Xung đột đồng bộ ở quy tắc 4 có test với `FileWatching` giả.
7. Mở thư viện 5.000 bài hát dưới 2 giây trên Linux CI (ghi số vào PR).
